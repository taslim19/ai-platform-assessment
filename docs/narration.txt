This project implements the AI question answering assessment as a small, deployable FastAPI service. The required endpoints are login, chat, health, and metrics. The service combines JWT authentication, role based authorization, Redis coordination, PostgreSQL persistence, and an OpenAI compatible provider integration. It also includes container deployment, automated tests, and a migration design. The important distinction is between working application features and future production extensions. The project does not claim a live five hundred requests per second deployment.

A client first logs in with a provisioned username and password. Passwords are hashed, and signed access tokens carry an expiry, issuer, and audience. Chat requires the user or admin role; metrics requires admin. Read only accounts cannot spend tokens by invoking generation. Each chat request is validated, checked against shared Redis controls, and sent through the logical LLM gateway. PostgreSQL stores identity and request metadata, without persisting raw conversations by default. Provider secrets remain environment configuration, not source code. Production ingress must add TLS.

The LLM gateway uses asynchronous HTTP, bounded timeouts, and a total operation deadline. Transient errors receive bounded retries with backoff and jitter. An optional fallback can use another model or endpoint. Permanent authentication failures are not blindly retried. Redis coordinates admission across replicas using rate limits and expiring concurrency leases. If Redis is unavailable, admission fails closed to protect the provider and budget. Metrics track request latency, provider outcomes, and token usage without high cardinality user labels. Request identifiers support investigation without logging private prompts.

Docker Compose provides PostgreSQL, Redis, the API, and an Nginx load balancer. Schema migration is a release step, not a race between API replicas. The Kubernetes examples add horizontal scaling, probes, and disruption protection, while assuming managed data services. CPU autoscaling is only a baseline. For network bound inference, in flight requests and queue age are often better signals. At five seconds average latency, one hundred requests per second means about five hundred concurrent provider calls. Five hundred requests per second means about twenty five hundred. More API pods cannot manufacture provider token or request quota.

For the single server migration, first measure the existing workload, inventory local state, and establish recovery targets. Move durable data to managed PostgreSQL and coordination to managed Redis. Use backward compatible schema changes and rehearse data migration. Then deploy at least two container replicas behind a load balancer, test privately, and gradually shift traffic with canary checks and a rollback plan. If the old database cannot replicate safely, a short write freeze is more honest than promising zero downtime. Managed ECS can be simpler than Kubernetes for a small team. Production identity should move to OIDC with verified access tokens and permission mapping.

The repository includes isolated tests and instructions for running the stack with a real provider key. Verification results are recorded separately so tests, deployment examples, and untested external integrations are not confused. Optional caching is disabled by default and isolated per user when enabled. Long running jobs would use a durable queue, owned job records, retry limits, and dead letter handling; that asynchronous extension is documented rather than presented as implemented. Before a real launch, finish live provider and infrastructure checks, automate metrics credential renewal, validate quota budgets, test backups, and run a controlled load test against the agreed service objectives.
